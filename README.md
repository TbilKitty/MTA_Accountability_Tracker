# Baltimore Transit Accountability

Independent, reproducible monitoring of Maryland MTA local bus schedules, alerts, and (when authorized) real-time updates. **Starter system, not a validated finding of service failure.**

## Start
1. Create a private GitHub repository initially; upload this project, keeping `.env`, `data/raw/`, and identifiable rider reports private.
2. Install Python 3.11+; run `pip install -r requirements.txt`.
3. Run `python -m src.collect --static` to download and archive the official local-bus GTFS schedule; run `python -m src.collect --alerts` to archive service alerts.
4. Run `python -m src.schedule --date 2026-10-15 --stop STOP_ID` after finding a stop ID in `data/processed/stops.csv` (generated by static collection).
5. Obtain Swiftly API access using https://www.mta.maryland.gov/developer-resources . Consult `docs/REALTIME_SETUP.md` before enabling real-time collection.
6. Enter rider reports using `data/rider_reports_template.csv` copied to a private file. Analyze with `python -m src.report`.
7. Open `docs/index.html` locally after running report, or publish the **aggregated, non-identifying** `docs/` directory via GitHub Pages.

## Important limitations
- Static schedules cannot establish a bus arrived, departed, or passed a passenger.
- An absent vehicle position, missing trip update, or missing alert **does not establish a no-show**.
- The real-time adapter is deliberately disabled until the authorized API endpoint and credentials are configured and validated. No automated accusations or social posts are enabled.
- Rider reports are allegations unless corroborated; never expose a child's identity, stop-specific travel routine, employer, or personal contact details.
- Data gaps, provider errors, and feed outages must be logged; preserve original data and hashes.
- Estimates of time value are not proven wage losses, actual costs, or MTA liability.

See docs/METHODOLOGY.md, docs/EVIDENCE.md, docs/REALTIME_SETUP.md and docs/DEPLOYMENT.md.

## Child safety research module
See `docs/CHILD_SAFETY_RESEARCH.md` and `docs/CHILD_SAFETY_DATA_DICTIONARY.md` for sources, templates, privacy safeguards and evidentiary standards. The module contains **schemas and a research plan, not fabricated child abduction statistics**. Never commit filled restricted case records to GitHub.

## Education and family impact scenario tool
Open `docs/education-impact.html` in a browser or through GitHub Pages. Adjust students, delay, missed classroom minutes, parent pickups, additional car miles, and work hours with sliders. Export a labeled hypothetical JSON scenario. **This is not an empirical data source or a legal finding.**

## Why complaints alone are insufficient
The public dashboard includes a reporting-gap statement. See `docs/REPORTING_GAP.md` for the methodology and evidentiary limitations of complaint data and MPIA requests.

## Structural reporting barriers and accountability content
The public dashboard now highlights why complaint counts cannot be treated as the total number of failures, the unobservable bus-number problem, and why school-age riders should not bear the sole burden of reporting. Read `docs/PUBLIC_POSITION.md`, `docs/STRUCTURAL_REPORTING_BARRIERS.md`, and `docs/COMPLAINT_FORM_AUDIT.md`. New audit and comparison CSV templates are under `data/`. **The actual MTA complaint form requirements have not yet been verified.**
